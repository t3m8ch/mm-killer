# Архитектура

Публичный API каждого модуля — `index.ts`. Контракт oRPC определяет вход,
выход и типизированные ошибки до реализации обработчиков. Платформа не
зависит от предметных модулей. Сборка приложения связывает модули через
публичные API и передаёт обратные вызовы вместо обратных импортов.

Граф разрешённых зависимостей (стрелка от потребителя к поставщику):

- invitations → courses
- tasks → courses
- attempts → tasks
- reviews → attempts
- git → attempts
- notifications → tasks
- каждый модуль → platform
- app → публичные API модулей, platform

Курсы владеют участием, ролями, подгруппами и состоянием курса; попытки —
допусками и переходами по цепочке. Только владелец таблицы может писать в
неё. Чтение через join допустимо в рамках направленного графа.

Тесты вызывают публичный oRPC API с настоящим Postgres и управляемыми часами.
Обычные тесты откатывают транзакцию, гонки используют независимые соединения.
Вспомогательный тестовый код запрещён в предметном коде.

UI модулей использует Mantine и платформенные компоненты. Собственные CSS,
`className`, `style` и UI DSL запрещены. Начальная загрузка выполняется в loader,
данные читаются через useSuspenseQuery. Ошибки и загрузка обрабатываются на
границе маршрута.

Проверка генератора создаёт тестовый модуль только во временном проекте.

## Серверный код и клиентская сборка

Import protection TanStack Start настроена в `vite.config.ts`: серверные модули
приложения и модулей, Node.js built-ins, `pg`, `pg-pool`, `drizzle-orm`,
`@orpc/server` и `nitro` запрещены в клиентском коде. Нарушение вызывает ошибку
при разработке и сборке. Стандартная защита файлов `*.server.*` сохраняется.
Контракты oRPC доступны клиенту; `import type` удаляется компилятором и допустим.
Серверные ветки TanStack Start удаляются из клиентской сборки до проверки границ.

`pnpm test:bundle` запускает реальные сборки во временном проекте: допустимый
клиент и импорт типа должны собираться, прямой серверный импорт, реэкспорт
и динамический импорт — завершаться ошибкой import protection. Проверка использует
конфигурацию проекта и запускается в CI. Новые серверные библиотеки добавлять
в запреты при их подключении. Защита импортов не проверяет произвольные секреты,
встроенные в строковые литералы или публичные переменные окружения.
