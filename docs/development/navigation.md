# Общая навигация

Реализация #4 повторяет вариант A ветки `prototype/issue-4-navigation`:
панель 300 px, хедер 60 px, единое дерево с эмодзи и Phosphor regular,
липкие название/«Все задания» и разделы курса, профиль внизу, темы в хедере.
Оболочка MergeMinds и её CSS находятся в платформенном модуле навигации.
Предметные UI по-прежнему используют Mantine и публичные платформенные компоненты
без собственных CSS.

## Контракты и сборка

Файлы оболочки сгруппированы в `src/platform/navigation`: `contract.shared.ts`
с описаниями дерева и состояниями веток, `layout.ui.tsx` с оболочкой,
`sidebar.ui.tsx` с панелью и `styles.css` с оформлением.
`platform/public.ui.ts` экспортирует `AppLayout`, `Sidebar`, `CourseBranch`
и `Layout` с провайдером темы. Контракты доступны через `platform/public.shared.ts`.
Сборка навигации остаётся в `src/app/navigation.tsx`, подключение авторизации —
в общем защищённом маршруте `src/routes/_authenticated.tsx`.

Общий тип `Breadcrumb` экспортируется через `platform/public.shared.ts`, чтобы
предметные модули могли возвращать описания крошек без зависимости от приложения.
Он содержит только подпись и адрес, без сведений о дереве маршрутов.

`AppLayout` принимает путь, крошки, режим страницы, состояние перехода,
содержимое страницы и `renderSidebar`. Оболочка вызывает эту функцию с
`{ drawer: false }` для постоянной панели и с `{ drawer: true }` внутри Drawer.
Она управляет размещением и открытием панели.

`Sidebar` имеет собственный интерфейс: путь, доступные курсы, текущий курс,
`renderCourseBranch`, пользователь и вариант отображения `drawer`.
Сборка `NavigationComposition` передаёт в `renderSidebar` путь и текущий курс,
а вызывающий код добавляет данные курсов и пользователя и возвращает `Sidebar`.
Оба UI-компонента получают готовые данные; загрузка предметных данных и RPC
остаются снаружи. Ссылки рисуются штатным TanStack `Link`, который
получает готовые строковые URL. Отдельного `onNavigate` и ручного выполнения
переходов через обработчик кликов нет. Обработчик в Drawer только закрывает
панель при выборе ссылки, включая ссылку на текущую страницу.

Типизация TanStack Router использует регистрацию и расширения типов маршрутов
из приложения. Их неявные связи разрешены точечно через `accept_augmentations`
в обоих конфигах Easement. Обычные импорты файлов приложения и сервера остаются
запрещёнными. Причины использования форка и границы исключения описаны
в [документе об архитектуре](architecture.md#регистрация-типов-маршрутов).
Клиентскую сборку дополнительно проверяет Vite import protection.

`CourseBranch` отображает ожидание, ошибку с повтором или данные; фоновое
обновление сохраняет ссылки на экране. Несколько веток раскрываются независимо.

Сборка `app/navigation.tsx` читает `useMatches` и реестр `RouteNavigation`.
Каждый подключаемый модуль экспортирует через `public.shared.ts` чистую функцию
построения крошек из загруженных данных. Функция ничего не загружает и не рисует.
Сборка связывает её с ID маршрута, при необходимости добавляет фабрику Query
и извлечение текущего курса. Loader возвращает данные после `ensureQueryData`;
сборка подписывается через `useQueries` на тот же ключ и при обновлении кэша
снова вызывает чистую функцию. Никаких эффектов регистрации, глобального store
или передачи данных из дочернего компонента наверх нет.

`staticData.navigationMode` содержит только постоянный режим: `normal`, `diff`
или `public` (вход). На diff панель и отступ исчезают; кнопка открывает Drawer.
На ширине до 720 px навигация всегда в Drawer. Переход и Escape закрывают его.
При выходе с diff панель возвращается. Mantine сохраняет выбор темы в `localStorage`
и восстанавливает его после перезагрузки; системный режим отслеживает настройку
устройства. `ColorSchemeScript` в корневом документе применяет сохранённую тему
до гидратации, а `mantineHtmlProps` учитывает изменение атрибута темы на `<html>`.

## Подключение следующих модулей

В этой ревизии доступны только `/` и `/login`; настоящих модулей курсов,
заданий и попыток пока нет. Главная показывает пустое состояние. Ссылки
на будущие личные настройки и разделы не выводятся. Меню профиля вызывает
настоящий API выхода; проверка сессии и доступа остаётся на сервере.
Скрытая ссылка никогда не заменяет серверную проверку доступа.

Маршруты добавляются вместе с модулями: `/invites/$token`, `/settings`,
`/courses/$courseId`, `/courses/$courseId/settings`, `/courses/$courseId/members`,
`/courses/$courseId/tasks/$taskId`, `/courses/$courseId/attempts`,
`/courses/$courseId/attempts/$attemptId`. Используются числовые стабильные ID,
без названий и username. Фильтры списка принадлежат query-параметрам.
Крошки попытки строятся из данных «курс → задание → попытка», даже когда
задание отсутствует в пути. Для попытки маршрут объявляет режим `diff`.
Файлы и строки, дерево файлов и интеграция настоящего diff остаются в T07b.

## Проверка

`pnpm test:browser` запускает отдельное тестовое приложение с настоящими
TanStack Router, Query и настоящей оболочкой приложения. Его маршруты и данные находятся только
в `tests/fixtures/navigation`, не входят в дерево или сборку продукта.
Браузерные интеграционные сценарии layout лежат в `tests/browser/navigation.test.ts`, отдельная
конфигурация запуска всех сценариев из `tests/browser` — в `playwright.browser.config.ts`.
Только компонент стенда `navigation_fixture` может зависеть от сборки
приложения и сгенерированного дерева маршрутов; обычные тесты этих прав не имеют.

Проверяются
прямые URL, активное задание, независимые ветки, кэш, обычный/diff layout,
переходы через Drawer, мобильный профиль, тема и Escape.
`pnpm test:e2e` проверяет настоящий вход, сессию и выход через меню профиля.

Оба Playwright-набора запускаются в CI после установки Chromium. Каждый запуск
поднимает собственный сервер: существующий процесс на нужном порту считается
ошибкой, чтобы проверка относилась к текущей ревизии. Пустой набор E2E считается ошибкой.

## Защищённые страницы и клиентский рендеринг

Общий маршрут `_authenticated` проверяет пользователя через QueryClient и
перенаправляет на `/login` при отсутствии сессии. Навигация и страницы читают
тот же клиентский кэш через QueryClientProvider; SSR-адаптер и перенос кэша
с сервера не используются. Корневой маршрут имеет `ssr: false`.

Nitro создаёт общую оболочку при сборке и раздаёт её для URL страниц.
Конфигурация и ограничения описаны в [договорённостях о запуске](deployment.md).
E2E проверяет вход, выход, обновление страницы, сохранение темы и отсутствие
персональных данных в исходном HTML.
