# Общая навигация

Реализация #4 повторяет вариант A ветки `prototype/issue-4-navigation`:
панель 300 px, хедер 60 px, единое дерево с эмодзи и Phosphor regular,
липкие название/«Все задания» и разделы курса, профиль внизу, темы в хедере.
CSS принадлежит платформе; предметные UI по-прежнему используют Mantine
и публичные платформенные компоненты без собственных CSS.

## Публичный контракт

`platform/public.shared.ts` экспортирует описания `Breadcrumb`, `NavigationLink`,
`NavigationCourse` и взаимоисключающие состояния `CourseBranchState`.
`platform/public.ui.ts` экспортирует `AppLayout`, `CourseBranch`, `NavigationItem`.
Layout принимает готовые крошки, доступные курсы, текущий курс, режим страницы,
обработчик перехода и функцию отображения независимо загружаемой ветки.
Он не импортирует предметные модули, роутер приложения или RPC.
`CourseBranch` отображает ожидание, ошибку с повтором или данные; фоновое
обновление сохраняет ссылки на экране. Несколько веток раскрываются независимо.

Сборка `app/navigation.tsx` читает `useMatches` и реестр `RouteNavigation`.
Каждый подключаемый модуль экспортирует через `public.shared.ts` чистую функцию
построения крошек из загруженных данных. Функция ничего не загружает и не рисует.
Сборка связывает её с ID маршрута, при необходимости добавляет фабрику Query
и извлечение текущего курса. Loader возвращает данные после `ensureQueryData`;
сборка подписывается через `useQueries` на тот же ключ и при обновлении кэша
снова вызывает чистую функцию. Никаких эффектов регистрации, глобального store
или передачи данных из дочернего компонента наверх нет.

`staticData.navigationMode` содержит только постоянный режим: `normal`, `diff`
или `public` (вход). На diff панель и отступ исчезают; кнопка открывает Drawer.
На ширине до 720 px навигация всегда в Drawer. Переход и Escape закрывают его.
При выходе с diff панель возвращается. Тема живёт в Provider до перезагрузки;
системный режим отслеживает настройку устройства средствами Mantine.

## Подключение следующих модулей

В этой ревизии доступны только `/` и `/login`; настоящих модулей курсов,
заданий и попыток пока нет. Главная показывает пустое состояние. Ссылки
на будущие личные настройки и разделы не выводятся. Меню профиля вызывает
настоящий API выхода; проверка сессии и доступа остаётся на сервере.
Скрытая ссылка никогда не заменяет серверную проверку доступа.

Маршруты добавляются вместе с модулями: `/invites/$token`, `/settings`,
`/courses/$courseId`, `/courses/$courseId/settings`, `/courses/$courseId/members`,
`/courses/$courseId/tasks/$taskId`, `/courses/$courseId/attempts`,
`/courses/$courseId/attempts/$attemptId`. Используются числовые стабильные ID,
без названий и username. Фильтры списка принадлежат query-параметрам.
Крошки попытки строятся из данных «курс → задание → попытка», даже когда
задание отсутствует в пути. Для попытки маршрут объявляет режим `diff`.
Файлы и строки, дерево файлов и интеграция настоящего diff остаются в T07b.

## Проверка

`pnpm test:browser` запускает отдельное тестовое приложение с настоящими
TanStack Router, Query и публичным UI. Его маршруты и данные находятся только
в `tests/fixtures/navigation`, не входят в дерево или сборку продукта.
Браузерные интеграционные сценарии layout лежат в `tests/browser/navigation.test.ts`, отдельная
конфигурация запуска всех сценариев из `tests/browser` — в `playwright.browser.config.ts`.
Только компонент стенда `navigation_fixture` может зависеть от сборки
приложения и сгенерированного дерева маршрутов; обычные тесты этих прав не имеют.

Проверяются
прямые URL, активное задание, независимые ветки, кэш, обычный/diff layout,
переходы через Drawer, мобильный профиль, тема и Escape.
`pnpm test:e2e` проверяет настоящий вход, сессию и выход через меню профиля.
