# Прототип навигации для #4

Одноразовый прототип для согласования сайдбара, хлебных крошек и перехода в проверку попытки. Не вливать в master. После настоящей реализации закрыть draft PR, сохранив ветку как источник. Выбор варианта ещё не сделан.

## Запуск

Из корня: `pnpm install --frozen-lockfile`, затем `pnpm prototype`.
Команда использует существующее окружение `mise.toml`; mise и инструменты проекта должны быть установлены. Прототипу не нужны миграции, seed или подключение к БД: сервер использует стандартную конфигурацию, но экраны работают с данными в памяти и не вызывают API.

Открыть `/prototype/courses/1?variant=A`. Все страницы живут под `/prototype/`, чтобы не менять настоящие вход и главную. После префикса сохранены согласованные пути и числовые ID. Изменения форм сбрасываются после перезагрузки.

## Варианты

- **A — единое дерево:** общие ссылки, все курсы и разделы выбранного курса в одной панели. [Скриншот](variant-A.png).
- **B — курсы + разделы:** узкая панель выбора курса, отдельное меню разделов; выбор соседнего курса из крошки. [Скриншот](variant-B.png).
- **C — рабочее пространство:** общий хедер, переключатель курса над контекстным меню; соседние задания доступны из крошки. [Скриншот](variant-C.png).

Переключатель снизу и клавиши ← / → меняют `?variant=`, сохраняя страницу, роль и фильтр. Стрелки в полях и меню не перехватываются. Переключатель виден только в dev. Под «Состояние» показаны параметры прототипа. Роль влияет только на видимость ссылок, это не реализация прав доступа.

## Липкие разделы курса

В едином дереве «Попытки», «Участники» и «Настройки курса» собраны в липкий блок у нижней границы прокручиваемого списка. Пока листаются задания раскрытого курса, его разделы остаются доступны. Название курса и «Все задания» объединены в липкий блок сверху: его высота определяется содержимым, включая переносы длинного названия. Между верхним и нижним блоками прокручиваются задания. Оба блока ограничены своей веткой: при уходе к другому курсу прокручивается вместе с ней. Фон закрывает проходящие под ним задания; в конце списка все задания можно прокрутить выше блока. В меню на diff и на мобильном работает так же; у студента нет настроек курса. [Нижний блок](sticky-course-actions.png). [Верхний и нижний блоки вместе](sticky-course-context.png).

## Симуляция среднего интернета

При первом открытии страницы данные приходят с искусственной случайной задержкой: 0,7–1,6 секунды, для diff — 1,4–2,6 секунды. Фильтры тоже ждут загрузки. Предзагрузка ссылок отключена. Это модель ожидания данных, а не ограничение реальной скорости сети или загрузки ресурсов.

Пока запрос выполняется, каркас остаётся на экране, в хедере показано «Загрузка…», прежнее содержимое приглушено и недоступно для действий. Навигация остаётся рабочей: можно передумать и выбрать другой курс, после завершения открывается последний выбранный экран. В «Состоянии» видны `loading` и задержка последнего завершённого запроса `delayMs`. [Вид во время загрузки](loading.png).

## Кэш запросов

Моковый запрос страницы теперь использует настоящий TanStack Query: loader вызывает `ensureQueryData`, экран подписывается на тот же запрос через `useQuery`. Данные свежие 30 секунд, неиспользуемые записи хранятся 5 минут. Свежий повторный переход обходится без задержки. После устаревания данные показываются сразу, а обновление идёт в фоне с прежней сетевой задержкой; «Обновление…» не блокирует содержимое. [Фоновое обновление](cache-refresh.png).

Ключ запроса включает путь и роль; для списка попыток — ещё статус фильтра. Вариант оформления не входит в ключ. Данные первого серверного открытия передаются клиентскому запросу через `initialData` с временем загрузки, без повторного ожидания после гидрации. Кэш живёт в памяти вкладки, без localStorage; перезагрузка начинает новый сеанс. Это кэш моковых запросов страниц, а не окончательная модель запросов предметных модулей.

Кнопка «Обновить кэш» в нижнем баре вызывает `invalidateQueries` только для запросов прототипа: открытые страницы и ветки обновляются в фоне с сетевой задержкой, закрытые остаются в кэше, но становятся устаревшими. При следующем раскрытии они показываются сразу и обновляются в фоне. Во время обновления кнопка показывает ожидание и временно недоступна. [Кнопка в действии](cache-button.png).

Проверить: открыть курс, уйти в другой и вернуться; затем вернуться после 30 секунд. В «Состоянии» доступны ключ запроса, `fromCache`, `refreshing` и время обновления данных. Отдельные фильтры и роли кэшируются независимо.

## Задания в едином дереве

В варианте A у каждого курса есть стрелка раскрытия: она открывает или сворачивает меню без перехода на страницу курса. Внутри — «Все задания», прямые ссылки на задания, попытки, участники и настройки. Название курса по-прежнему открывает его страницу. Можно раскрыть несколько курсов и перейти к заданию другого курса напрямую. Активное задание выделено; при переходе по URL текущий курс раскрывается автоматически.

То же дерево доступно в панели за кнопкой на diff и на мобильном экране. Содержимое раскрытого курса загружается отдельным моковым запросом TanStack Query с задержкой 0,7–1,6 секунды. До ответа внутри курса показано «Загрузка раздела…», стрелка позволяет свернуть его и во время ожидания. Задания рисуются из результата запроса. Свежий кэш (30 секунд, хранение 5 минут) открывается сразу; устаревшие данные остаются доступны при фоновом обновлении. Маленький спиннер справа в строке «Все задания» показывает обновление без изменения высоты ветки и положения ссылок. Ключ включает ID курса и роль. Основной сайдбар и меню за кнопкой используют общий кэш. Сворачивание не отменяет запрос: ответ остаётся в кэше. Переходы на страницы используют отдельные задержки и кэш. [Ожидание содержимого ветки](tree-loading.png). [Задания в сайдбаре](sidebar-tasks.png).

## Что попробовать

Открыть «Мои курсы», выбрать курс, затем задание и попытку. На [диффе](diff.png) обе части основной навигации скрыты без отступа; кнопку навигации оставить в хедере рядом с крошками. Кнопка открывает [панель поверх содержимого](diff-navigation.png). Дерево файлов остаётся слева, переходы и Escape закрывают панель. При выходе из diff возвращается обычная навигация.

Другие экраны: вход, приглашение, личные настройки, настройки курса, участники, список попыток с фильтром в query. На настройках курса можно изменить название и проверить немедленное обновление крошек (это локальное состояние, не интеграция с Query). Второй курс имеет длинное название. Переключатель роли позволяет посмотреть скрытие преподавательских ссылок. [Мобильная панель](mobile.png).

Содержимое страниц, сдача задания и проверка — заглушки. Крошки строятся по моковым данным, у попытки известно задание независимо от глубины URL. Публичные API модулей, useMatches, staticData, запросы настоящих модулей и серверные права остаются для реализации #4 и соответствующих модулей. Это материал для выбора UX, не выполнение всех критериев #4.

Какую структуру выбрать и какие части совместить? Оценивать скорость перехода между курсами, читаемость длинных крошек и доступность навигации на diff. После выбора зафиксировать решение в #4 и переписать победивший вариант под настоящий контракт приложения. Прототип пока не подтверждает ни один вариант.
